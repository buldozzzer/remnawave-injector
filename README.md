# Remjector
## Возможности

1. Изменение подписок в форматах Base64 и JSON для разных клиентов.
2. Добавление собственного HTML и JavaScript на страницу подписки.

## Схема работы

`Обратный прокси` ↔ `Remjector` ↔ `Страница подписки Remnawave`

## Развёртывание

1. Создайте файл конфигурации.
    ```
    cp ./config.example.yml ./config.yml
    ```
2. Настройте параметры в `config.yml`.
3. В настройках обратного прокси замените адрес сервиса `remnawave-sub-page` на `remjector`.
4. Запустите контейнер.
    ```
    docker compose up -d
    ```

## Добавление конфигураций в JSON-подписку

В `config.yml` включите `subscription_modification.json.enabled`. При переходе с
`append_configs` перенесите общие поля конфигов в `outbound_template`, а объекты
подключений в `append_outbounds`. Оба параметра находятся в секции
`subscription_modification.json`.

Для каждого объекта из `append_outbounds` создаётся отдельный конфиг на основе
`outbound_template`. Объект подключения становится первым элементом `outbounds`,
за ним идут вспомогательные объекты из шаблона, если они заданы.

Параметр `remark` задаёт общий префикс поля `remarks` в добавленных конфигах.
По умолчанию используется `🇷🇺 Скорая помощь 🚑 #`, к которому дописывается
номер начиная с 1.

Объекты добавляются в конец массива ответа в порядке из файла, после применения
`replacements` к исходному ответу. Для всех пользователей используются одни и
те же объекты. Добавление можно отключить через `enabled_append: false` внутри
секции `json`.

Чтобы отключить только текстовые замены, задайте `enabled_replace: false`
в секции `json`. По умолчанию текстовые замены включены.

## Удаление полей JSON для клиентов Windows

Включите JSON-модификации и задайте имена удаляемых ключей в `config.yml`.

```yaml
subscription_modification:
  json:
    enabled: true
    windows_key_removal:
      enabled: true
      keys:
        - "routing"
        - "dns"
```

Имена ключей учитывают регистр. Поля удаляются целиком с верхнего уровня
объекта подписки или каждого профиля в массиве, включая добавленные профили.
Для вложенных полей используйте `paths`. Каждый путь начинается от корня
профиля. Строки обозначают ключи объектов, числа — индексы массивов с нуля.
Например, чтобы удалить `finalmask` из `streamSettings` первого `outbound`,
задайте в `windows_key_removal`:

```yaml
paths:
  - ["outbounds", 0, "streamSettings", "finalmask"]
```

Если путь отсутствует в профиле, он пропускается.

Чтобы удалить ключ на любой глубине во всех элементах `inbounds` каждого
профиля, перечислите его в `windows_key_removal.inbound_keys`:

```yaml
inbound_keys:
  - "finalmask"
```

Поиск проходит по вложенным объектам и массивам внутри `inbounds`.

Для всех элементов `outbounds` каждого профиля используйте
`windows_key_removal.outbound_keys`:

```yaml
outbound_keys:
  - "finalmask"
```

Поиск проходит и по вложенным объектам и массивам, включая `streamSettings`.

По умолчанию правило ищет слово `Windows` в заголовке `User-Agent` без учёта
регистра. Если у клиента другой заголовок, задайте регулярное выражение
`user_agent_regex` в секции `windows_key_removal`. Клиенты из
`user_agent_exceptions` пропускают все модификации подписки.
